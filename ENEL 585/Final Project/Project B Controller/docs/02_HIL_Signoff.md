# HIL Sign-off: Build, Run and Checklist

Goal: demonstrate on the remote Typhoon HIL, before any closed-loop hardware operation, the
checklist in Appendix C: **startup, stable operating points, every station-sheet transient,
relevant limits and protective shutdown**. Plan to sign off at the start of Bench 2 (Fri Nov 20),
so run through this whole document on the remote HIL before then, at least once with every
member present.

Our assigned HIL computer on the remote farm is **SSE-6Y8G3H4** (Oct 29 station list, Station 5).

Files you need: `plecs/Controller.plecs` (firmware), the Project B HIL files from D2L
(`ENEL585_F26_ProjectB_sch_20261029.tse`, `ENEL585_F26_ProjectB_HIL_Panel_20261029.cus`), and
`Launchpad_TMS320F28P550SJ9.ccxml`.

## 1. Open the models on your own computer

1. Open `plecs/ProjectB_Sim.plecs` and run it (1.4 s). Compare its scopes with
   `figures/sim_*.png`: soft start to 25 V rms, step to 30 V rms at 0.6 s and back at 0.8 s, load
   step at 1.0 s and back at 1.2 s. If it matches, the model is good for the design review.
2. Open `plecs/Controller.plecs`. It should show: two ADC blocks (ADC_A, ADC_B), two demuxes, the
   enableswitch with enable/disable constants, seven tunable constants, a mux, the C-Script
   `PB_controller`, a 12-way demux, PWM (ePWM1, leg A), PWM1 (ePWM2, leg B), Protection, a scope, the
   CPU load display and four displays.

These files were generated by a script and **have not been opened in PLECS yet** (no licence where
they were made). Every block was copied from course files that work (Lab 2's LaunchPad model,
Tutorial 5, Lab 2's simulation), so they should load. If PLECS reports a problem:

| Symptom | Fix |
|---|---|
| A wire attaches to the wrong port of a Mux | Reconnect it by hand. Mux inputs must be, top to bottom: v_dc, i_L, v_o, i_o, enable, Vref_rms, Kp, Ki, FF, Trip_vo, Trip_iL, Trip_io |
| Messy diagonal wires | Cosmetic. Tidy them if you want; nothing changes |
| The C-Script fails to compile | Open its dialog and compare with `plecs/controller_cscript_sections.txt`; report the error message |
| The file will not open at all | Manual build, below |

**Manual build (fallback, about 30 minutes).** Open Lab 2's `spwm_unipolar_ti_launchpad.plecs` and
save it as `Controller.plecs` (the name matters: it sets `Controller.out` and the `Controller_P`
prefix).
1. Paste the initialization commands from the generated file (open it in a text editor, or use
   `FW_INIT` in `gen_plecs.py`).
2. Copy ADC1, ADC2 and Control Task Trigger from Tutorial 5's model. Rename the ADC blocks to ADC_A
   and ADC_B, set Input to `ADC_A_CH` and `ADC_B_CH`, Scale 1, Offset 0.
3. Wire the Tutorial 5 PWM block's trigger output to both ADC triggers, and ADC_B's
   end-of-conversion to Control Task Trigger.
4. Replace `m_i` with the seven constants (Vref_rms = 25, Kp = Kp0, Ki = Ki0, FF = 1, Trip_vo = 0,
   Trip_iL = 0, Trip_io = 0).
5. Set the C-Script to 12 inputs and 12 outputs, sample time `Tctrl`, and parameters as in the
   text file. Paste the four code sections.
6. Feed it through a 12-input mux in the order above, and send its outputs to a 12-output demux:
   output 1 to PWM (ePWM1), output 2 to PWM1 (ePWM2), output 3 to the Protection block input.
7. Set both PWM blocks to carrier `fsw` and dead time `deadtime`. Copy the Protection block from
   Tutorial 5 (enable GPIO `PWR_DSP_GPIO`).
8. Add Vref_rms, Kp, Ki, FF, Trip_vo, Trip_iL and Trip_io to the Parameter Inlining exceptions.

## 2. Build the firmware (your computer)

1. Coder → Coder options… → Target: TI28P55x (already set). Set **Build type: Build only**
   for the remote HIL.
2. Coder options → Parameter Inlining: the exceptions must include `enableswitch`, `Vref_rms`,
   `Kp`, `Ki`, `FF`, `Trip_vo`, `Trip_iL`, `Trip_io`.
3. Build. From `Controller_codegen` copy `output_TI28P55x/Controller.out` and `Controller.h` to
   the HIL computer, with `Launchpad_TMS320F28P550SJ9.ccxml`.
4. Open `Controller.h` and note the exact field names. You should find, in the parameter struct,
   `enableswitch_SwitchState`, `Vref_rms_Value`, `Kp_Value`, `Ki_Value`, `FF_Value`,
   `Trip_vo_Value`, `Trip_iL_Value`, `Trip_io_Value`. In the block-output struct, look for the
   ADC outputs (pin voltages) and the C-Script output vector (12 values, order in §5).
5. Record in the bench log: date and time of the build, the git commit of this folder, and
   the CPU load shown by the `%` display (in External Mode on the bench).

## 3. Set up the HIL plant (Typhoon, on the HIL computer)

1. Open `ENEL585_F26_ProjectB_sch_20261029.tse`. In **Model Settings → Model initialization**
   set:
   ```
   R_load_A = 25.0
   R_load_B = 25.0
   ```
   (A alone = 25 Ω = OP1 load; A and B together = 12.5 Ω = OP2 load. The default is 50/25.)
2. Compile, open `ENEL585_F26_ProjectB_HIL_Panel_20261029.cus`, start the simulation.
3. On the panel: probe settings **VProbe1 and VProbe2 10:1, CProbe1 and CProbe2 100 mV/A**;
   ITECH set point **55 V**; ITECH output **on**; **Load A on, Load B off**.

## 4. Flash and run (CCS, as in the Remote HIL Quick Start)

File → Open Folder (the folder with the three files) → right-click the .ccxml → Start
Project-less Debug → select C28xx_CPU1 (Connect Target if needed) → Run → Load Program →
`Controller.out` → Continue (F5). In Watch add `Controller_P` and `Controller_B`.

## 5. Watch variables

| Field | Default | Meaning |
|---|---|---|
| `Controller_P.enableswitch_SwitchState` | 0 | 1 = run (soft start), 0 = stop and acknowledge a fault |
| `Controller_P.Vref_rms_Value` | 25 | Output reference, V rms. Clamped to 34.6 V rms. Changes take effect at the next positive zero crossing |
| `Controller_P.Kp_Value` | 0.01 | Proportional gain. Do not raise above 0.015 (resonant peak) |
| `Controller_P.Ki_Value` | 60 | Resonant gain, 1/s |
| `Controller_P.FF_Value` | 1 | Reference feedforward: 1 on, 0 off (loop-only test) |
| `Controller_P.Trip_vo_Value` | 0 | Test level for the v_o trip; 0 = design value (50 V). Can only lower it |
| `Controller_P.Trip_iL_Value` | 0 | Same for i_L (7 A) |
| `Controller_P.Trip_io_Value` | 0 | Same for i_o (6 A) |

C-Script outputs (in `Controller_B`, watch only), in order:

| # | Signal | # | Signal |
|---|---|---|---|
| 0 | d_A, leg A duty | 6 | x_amp, resonant correction amplitude (V) |
| 1 | d_B, leg B duty | 7 | v_ref, instantaneous reference (V) |
| 2 | PWM enable | 8 | v_dc (V) |
| 3 | **fault bits** | 9 | i_L (A) |
| 4 | amp, reference amplitude (V peak) | 10 | v_o (V) |
| 5 | m, modulation index | 11 | i_o (A) |

Fault bits: 1 = v_o over, 2 = i_L over, 4 = i_o over, 8 = v_dc over, 16 = v_dc under while running,
32 = v_o polarity. Values add (for example 3 = bits 1 and 2).

## 6. Checklist with expected results

Expected values are from the switched simulation with the HIL sensing model
(`design/results_sim.json`). The HIL regulates about 1 % below the reference: its sensing model
passes part of the capacitor ripple, which the valley sample turns into a small 60 Hz error. Read
voltages and currents on the SCADA panel's own meters or scopes, not only from Watch (the Watch
values are single samples).

| # | Test | How | Expect | Pass if |
|---|---|---|---|---|
| 1 | Readback, PWM off | enableswitch 0 | v_dc ≈ 55 V; v_o, i_L, i_o ≈ 0; fault 0 | v_dc within 1 V of 55 V; currents under 0.1 A |
| 2 | Startup | enableswitch 1 | Starts at the next zero crossing; amplitude ramps at 100 V/s (0.35 s to 35.4 V); no fault | Smooth ramp, no trip |
| 3 | OP1 | Load A only, Vref 25 | v_o 24.7 V rms; i_L 2.1 A rms, 5.1 A peak; ripple 7.5 A pk-pk; I_dc 0.49 A; m peak 0.65 | v_o within 2 % of 25 V; stable |
| 4 | OP2 | Vref 30, then Load B on | v_o 29.9 V rms; i_L 3.0 A rms, 7.3 A peak; ripple 7.7 A pk-pk; I_dc 1.36 A; m peak 0.85 | Within 2 %; no trip |
| 5 | Load step (station sheet) | At Vref 30: Load B on, then off | Dip about 3 % for 1 to 2 cycles, recovered in about 3 cycles; no trip; i_L peak 7.3 A | Recovers, no trip |
| 6 | Reference step (station sheet) | Load A only: Vref 25 → 30 → 25 | New amplitude from the next zero crossing; within 2 % in 2 cycles; overshoot about 1 % | As expected |
| 6b | Loop-only reference step | FF 0, repeat 6, then FF 1 | Amplitude approaches the new value with τ ≈ 17 ms; within 2 % after 4 cycles | Matches the prediction (§7 of the design review) |
| 7 | v_o trip | OP2 running, Trip_vo = 40 | Fault 1 within one cycle, all gates off | Trips, PWM off |
| 8 | i_L trip | OP1 running, Trip_iL = 1.2 | Fault 2 | Trips |
| 9 | Reset | enableswitch 0, Trip values back to 0, enableswitch 1 | Clean restart with soft start | Restarts |
| 10 | DC overvoltage | Running, ITECH set point 58.5 V | Fault 8 when v_dc passes 58 V | Trips |
| 11 | ITECH off while running | ITECH output off | v_dc falls (about 40 ms at OP1); fault 16 at 35 V | Trips before v_dc collapses |
| 12 | Start inhibit | ITECH at 30 V, enableswitch 1 | Stays off (v_dc < 40 V) | No switching |

For every test, record in the bench log: time, firmware build, Watch settings, SCADA settings, and
save a capture of v_o and i_L. The report needs these as "relevant HIL results".

**Before the TA**: run tests 1 to 11 in that order, explain each response in terms of the design
(soft start, feedforward, the envelope time constant, why the load step dips, what each trip
does), and identify the firmware build and model versions.

## 7. Known differences: HIL model vs bench

- HIL sensing filter: one pole and a zero (the bench has two poles), so less filtering at the LC
  resonance. The design has margin for both (§6.5 of the design review).
- HIL output about 1 % low; the bench about 0.5 to 1.3 % high. Both come from the measurement chain,
  not the controller.
- The ITECH is modelled as a constant-voltage source behind 0.05 Ω with a ±10 A limit.
- Dead time and device drops in the HIL power stage come from Typhoon's inverter model; the
  dead-time notches and THD may differ from the bench.
