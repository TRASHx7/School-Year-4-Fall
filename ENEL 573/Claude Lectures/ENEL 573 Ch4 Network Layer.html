How a packet crosses many different networks to reach the right host: what the network layer does, the IPv4 header and fragmentation, classful addresses, subnet and supernet masks, prefix blocks, longest prefix matching and Bellman-Ford routing. Every lecture example is worked step by step.

Start hereBig picture

The link layer (Chapter 3) moves a frame across one hop, between two nodes on the same network. Real traffic has to cross many different networks (Ethernet, Wi-Fi, satellite links, telephone networks) to reach a host on the other side of the world. The network layer makes that possible. It gives every connection a globally unique address, wraps transport-layer segments into IP datagrams, chops datagrams into fragments when a link cannot carry them whole, and lets every router decide which output link moves the datagram one step closer to its destination.

The chapter builds up in four steps. First, what the layer does and what an IP datagram looks like. Then how IPv4 addresses are written and split into classes. Then how masks carve address space into subnets, merge it into supernets and describe any block with a prefix length. Finally, how routers use those prefixes to forward packets, and how a routing algorithm (Bellman-Ford) fills in the tables.

Part 1 · The network layer and IP datagrams

Section 1What the network layer does

Each layer delivers data over a different distance:

  • The transport layer delivers data process to process (from one program to another).
  • The network layer delivers packets host to host, even when the two hosts sit on several different physical networks.
  • The data link layer delivers frames node to node (hop to hop), only between physically adjacent nodes on the same network.

So the link layer gets a packet across one hop, and the network layer strings those hops together into an end-to-end path. That is why network layer protocols run in every host and every router. On the sending host the network layer encapsulates transport segments into datagrams. Each router on the way examines the header fields of every IP datagram passing through it. On the receiving host the network layer pulls the segment out and hands it up to the transport layer.

The duties of the network layer

Example 1 (lecture): how S1 forwards a datagram from A to D
Host A sits on a LAN attached to interface f1 of router S1. S1 also has a second LAN on f2 and a link to a WAN on f3. Across the WAN, router S2 (interfaces f1 and f2) leads to one LAN and router S3 (interfaces f1 and f2) leads to the LAN of host D.

The datagram's header carries D's IP address. S1 looks that address up in its forwarding table. D is not on either of S1's LANs, so the entry for D's network points to the WAN side:

\[ \text{S1: } \text{forwarding table}\big[\,\text{address of D}\,\big] = \text{f3} \]

The datagram crosses the WAN and arrives at S3 on f1. S3's table says D's network is on its f2 LAN:

\[ \text{S3: } \text{forwarding table}\big[\,\text{address of D}\,\big] = \text{f2} \]

Along this host-to-host path the network layer runs in A, S1, S3 (and any routers inside the WAN) and D, while the transport layer runs only in A and D. Separately, the lecture's figure of one "Network" box sitting over Link1 to Link4 and PHY1 to PHY4 makes the internetworking point: one network layer runs over many different link and physical technologies.

Analogy

Sending a parcel across the country. The transport layer is the person who addresses the parcel to a named recipient inside a building. The network layer is the postal system that gets it to the right building using a street address. The link layer is each individual truck ride between two depots. Each depot (router) only looks at the address and picks the next truck; it never opens the parcel.

Tricky bits
  • Host to host (network) versus process to process (transport) versus node to node (link). Exams ask this directly.
  • Routers run the network layer but not the transport layer. Hosts run all five layers.
  • Routing and forwarding are different: forwarding is a table lookup in one router; routing is the algorithm that computes the tables.
  • "Best effort" means no guarantees at all, not "tries hard and usually guarantees delivery".
  • An address belongs to a connection (an interface), not to a machine. A router with three interfaces has three IP addresses.

header size, payload size and time to live

With no options, \(\text{HLEN} = 5\), so \(H = 20\) bytes. The largest HLEN value a 4-bit field can hold is 15, so a header is at most \(4\times 15 = 60\) bytes. When TTL reaches 0, the router discards the datagram, so a packet caught in a routing loop cannot circulate forever.

Example 2 (lecture): how much overhead with TCP?
TCP header \(= 20\) bytes, IPv4 header \(= 20\) bytes (40 bytes for IPv6).

Every TCP segment carried in IPv4 pays both headers:

\[ \text{overhead} = 20\ \text{bytes (TCP)} + 20\ \text{bytes (IP)} = 40\ \text{bytes} \]

plus whatever overhead the application layer adds. Over IPv6 the IP header alone is 40 bytes, so the total would be \(20 + 40 = 60\) bytes.

40 bytes per segment + application overhead
Analogy

The header is the shipping label on a box. It shows sender and receiver addresses, a "this side up" priority sticker (DSCP), "box 2 of 3" markings for split shipments (identifier, flags, offset), and a "return if not delivered within 64 transfers" stamp (TTL). The label analogy breaks down for the checksum: a real label has nothing that lets each depot detect a smudged address.

Tricky bits
  • Header length counts 4-byte words; fragment offset counts 8-byte units; total length counts bytes. Three different units in one header.
  • Total length includes the header. Payload \(= L - H\), not \(L\).
  • The IP payload includes the TCP header. If a question asks for application data, subtract the 20-byte TCP header too.
  • TTL is a hop count here, decremented once per router, not a time in seconds.
  • The checksum covers the header only, not the data.

Section 3Fragmentation and reassembly

Every link has an MTU (maximum transmission unit): the largest datagram its link-level frame can carry. Different link types have different MTUs. When a datagram is larger than the next link's MTU, the router fragments it: one large datagram becomes several smaller datagrams, each with its own IP header. The fragments travel independently and are reassembled only at the final destination, never at intermediate routers. Three header fields make this work:

  • Identification (16 bits): uniquely identifies a datagram from the source host, incremented by one for each datagram. It is copied into all fragments, so the destination knows that fragments with the same identification from the same source belong to one datagram.
  • Flags (3 bits): the first bit is reserved. The second is do not fragment: if it is 1, the datagram must not be fragmented. The third is more fragments: 1 means more fragments follow this one, 0 means this is the last (or only) fragment.
  • Offset (13 bits): the position of this fragment's data within the original datagram's data, measured in units of 8 bytes.

Because offsets count 8-byte units, every fragment except the last must carry a number of data bytes that is a multiple of 8.

\[ D_f = 8\left\lfloor \frac{\text{MTU} - H}{8} \right\rfloor \]
\[ n = \left\lceil \frac{L - H}{D_f} \right\rceil \]
\[ \text{offset}_k = \frac{k\,D_f}{8}, \qquad k = 0, 1, \dots, n-1 \]
\[ L_{\text{last}} = (L - H) - (n-1)\,D_f + H \]
data per fragment, number of fragments, offsets and the last fragment's length
\(D_f\) = data bytes carried by each full fragment, in bytes · \(\text{MTU}\) = maximum transmission unit of the outgoing link, in bytes · \(H\) = IP header length, in bytes (20 with no options) · \(L\) = total length of the original datagram, in bytes · \(n\) = number of fragments (no unit) · \(k\) = fragment index, starting at 0 (no unit) · \(\text{offset}_k\) = offset field of fragment \(k\), in 8-byte units · \(L_{\text{last}}\) = total length of the last fragment, in bytes · \(\lfloor\ \rfloor\) rounds down, \(\lceil\ \rceil\) rounds up

Tricky bits
  • Every fragment gets its own 20-byte header. Subtract the header from the MTU before splitting the data, and add it back to get each fragment's length.
  • Split the data (\(L - H\)), not the total length. Dividing 4000 by 1500 gives the wrong count.
  • The offset is a byte position divided by 8. Writing 1480 instead of 185 is the most common slip.
  • If \(\text{MTU} - H\) is not a multiple of 8, round it down to the nearest multiple of 8. Rounding up would exceed the MTU.
  • The more-fragments flag is 1 on every fragment except the last. The original unfragmented datagram has flag 0 and offset 0.
  • Reassembly happens only at the final destination.

Part 2 · IPv4 addresses and classes

Section 4IPv4 addresses in binary and dotted decimal

The address used at the network layer of the TCP/IP model is the Internet address or IP address. An IPv4 address is a 32-bit (4-byte) identifier that uniquely and universally defines a connection between a host or router and the network. Two consequences follow:

  • A router connects several networks, so it has one IP address per interface. In the lecture's figure, one router has interfaces 223.1.1.4, 223.1.2.9 and 223.1.3.27, one on each of three networks.
  • A host with two interfaces (for example wired Ethernet and 802.11 wireless) has two IP addresses.

Addresses are unique (each connection has a different address) and universal (any host that wants to connect to the Internet must accept the same addressing system).

People write the 32 bits as four decimal numbers separated by dots, X.Y.W.Z, called dotted decimal notation. Each number stands for one byte, so it is between 0 and 255.

\[ \text{byte value} = \sum_{i=0}^{7} b_i\,2^{i} \]
\[ \text{address space} = 2^{32} = 4\,294\,967\,296 \ \text{addresses} \]
converting one byte, and the size of the IPv4 address space
\(b_i\) = bit \(i\) of the byte, 0 or 1, counted from the right (bit 0 has weight 1, bit 7 has weight 128) · \(i\) = bit position (no unit) · the bit weights from left to right are 128, 64, 32, 16, 8, 4, 2, 1
Example 4 (lecture): binary to dotted decimal
Address in binary: 10000001 00001011 00001011 11101111

Convert each byte separately by adding the weights of its 1 bits:

\[ \begin{aligned} 10000001 &= 128 + 1 = 129\\ 00001011 &= 8 + 2 + 1 = 11\\ 00001011 &= 11\\ 11101111 &= 128 + 64 + 32 + 8 + 4 + 2 + 1 = 239 \end{aligned} \]
129.11.11.239

The address space has \(2^{32}\) addresses, more than 4 billion, as the lecture says.

Analogy

An IP address is like a phone number assigned to a phone line, not to a person. A house with two lines has two numbers, and a switchboard (router) that connects to three exchanges has a number on each one. Dotted decimal is just a friendlier way of reading a long string of digits, the way a phone number is split into groups.

Tricky bits
  • Each dotted-decimal number is one byte: 0 to 255. A value like 256 or 300 cannot appear in an IPv4 address.
  • Read the bits of a byte left to right with weights 128 down to 1. Reading them in reverse gives a completely different number.
  • Always write all 8 bits of each byte, leading zeros included (11 is 00001011, not 1011). Masks and prefixes count bits from the left, so missing zeros shift everything.
  • Each byte has 256 possible values (0 to 255), so the space is \(256^4 = 2^{32}\), not \(255^4\).

Section 5Classful addressing and its problems

IP addresses are hierarchical: each one has a network id (netid) part and a host id part. Routers only need the network part, so routing tables hold network addresses rather than every individual host. In the original classful scheme, the first few bits of an address decide its class, and the class fixes where the split between netid and hostid falls.

Why classful addressing failed

  • Bad utilization. About 4 billion addresses should be enough for everybody, but handing them out in fixed-size sets wastes most of them. Class A blocks are too big and too few; millions of class A addresses are wasted. Class B blocks are larger than most organizations need, so many are wasted too, and class B ran out. Class C blocks (256 addresses) are too small for most organizations, and there are too many of them.
  • Routing tables grow very large, because every new network adds a table entry.

The short-term fixes are subnetting (Sections 6 and 7) and supernetting (Section 8), which let an addressing scheme meet the users' needs more exactly. The long-term fix is IPv6, with a much larger address space; the IPv4 shortage was one of the reasons behind it.

Analogy

Classful addressing is a car park that only sells parking in three sizes: a single space, a whole floor or the entire building. A company with 300 cars must buy the whole building and leave most of it empty, while a company with 2 cars wastes most of a floor. Subnetting and supernetting are the operator finally agreeing to sell blocks of any power-of-2 size.

Tricky bits
  • Decide the class from the first byte only: 0 to 127 A, 128 to 191 B, 192 to 223 C, 224 to 239 D, 240 to 255 E.
  • Class A has 7 netid bits, not 8: the leading 0 is fixed. Likewise B has 14 and C has 21.
  • Network address: hostid bits set to 0. Setting them to 1 gives the last address in the block (the broadcast address), not the network address.
  • Number of networks in a class and number of addresses in one network are different counts. Class B: 16 384 networks, each with 65 536 addresses.
  • Class D addresses are multicast; they have no netid and hostid split.

Part 3 · Subnets, supernets and prefixes

Section 6Subnet masks and the AND operation

In subnetting, one network is divided into several smaller groups (subnets). Each subnet has its own subnet address, but the whole set still appears as a single network to the rest of the Internet. The address now has 3 levels: main network, subnet and host. The bits that used to be the host id are partitioned into a subnet id and a smaller host id. For a class B address with an \(n\)-bit subnet id: 14-bit net id, \(n\)-bit subnet id, \((16-n)\)-bit host id. The net id plus subnet id is called the extended network prefix.

A subnet mask is a 32-bit pattern of 1s followed by 0s that marks where the split is: 1s over the network and subnet bits, 0s over the host bits. ANDing the mask with an IP address keeps the network and subnet bits and clears the host bits, which gives the network or subnet address.

\[ \text{subnet address} = \text{IP address} \;\text{AND}\; \text{mask} \]

Section 8Supernetting

Class C has many networks, but a block of at most 256 addresses may not be enough for an organization. Supernetting is the opposite of subnetting: the organization combines several class C blocks into one supernetwork with a larger range of addresses, which the rest of the Internet sees as a single network (one routing table entry). Two rules apply:

  • The number of blocks must be a power of 2 (2, 4, 8, ...).
  • The blocks must be contiguous in the address space, with no gaps between them.

The lecture's picture shows four class C networks X.Y.32, X.Y.33, X.Y.34 and X.Y.35 joined into the supernetwork X.Y.32.0 behind one router to the rest of the Internet.

A supernet mask is the class C default mask with some 1s removed. Removing \(k\) ones from /24 merges \(2^k\) class C networks; adding \(k\) ones to it (subnetting) splits one network into \(2^k\) subnets. The lecture's comparison uses \(k = 3\): /27 divides 1 network into 8 subnets, /21 combines 8 networks into 1 supernet.

\[ \text{blocks} = 2^{k}, \qquad n_{\text{super}} = 24 - k, \qquad \text{mask byte 3} = 256 - 2^{k} \]
\[ \text{D belongs} \iff \big(\text{D} \;\text{AND}\; \text{supernet mask}\big) = \text{first address} \]

\(k\) = number of 1s removed from the class C default mask (no unit) · \(n_{\text{super}}\) = supernet prefix length, in bits · D = destination address being tested · first address = the supernet address (lowest address of the first block)

Section 10Forwarding tables and longest prefix match

A router's forwarding table maps ranges of destination addresses to link interfaces, because listing every one of 4 billion addresses is impossible. Ranges that start and end on block boundaries can be written as prefixes, so each table entry is really "this prefix goes out of that interface". Ranges can overlap (a small block inside a bigger one), so the router needs a rule to choose between several matching entries.

Longest prefix matching: when looking for the forwarding table entry for a given destination address, use the longest address prefix that matches the destination address. The longest prefix is the most specific entry, the smallest network that contains the destination.

\[ \text{entry } (P, n) \text{ matches D} \iff \big(\text{D} \;\text{AND}\; \text{mask}_n\big) = P \]
\[ \text{chosen entry} = \text{the matching entry with the largest } n \]

Section 11Routing and the Bellman-Ford algorithm

The network layer guides packets from source to destination along a path that may cross many links. Its major function is routing: finding the best path for a particular transmission. Routers then forward packets according to the routing table that routing produces. A router is a box with input and output links, access to the routing table, and software that decides which of the possible paths is best.

A routing problem is modelled as a set \(S\) of \(N\) nodes (routers) and a set of link lengths \(\{d_{i,j},\ i, j \in S\}\), with \(d_{i,j} = \infty\) if there is no link from \(i\) to \(j\). A "good" routing algorithm has:

  1. simplicity;
  2. robustness to node and link failures;
  3. stability (fast adaptation to topology and traffic changes);
  4. optimality (low delay and high throughput);
  5. fairness.

Most routing algorithms are distributed: each node makes its own routing decisions, cooperating by exchanging information with its neighbours. Bellman-Ford is one of them.

The idea

The shortest path length from node \(i\) to the destination is the length of the arc to the node following \(i\) plus the shortest path length from that node to the destination. So each node only needs its neighbours' current estimates. At step \(h = 0\) the destination knows its distance is 0 and every other node's estimate is \(\infty\). At each step every node \(j\) advertises its estimate \(d_j^h\) to its neighbours. Node \(i\) then knows that sending a packet first to neighbour \(j\) costs about \(d(i,j) + d_j^h\), and picks the best neighbour.

\[ d_1^{h} = 0 \quad \text{for all } h \]
\[ d_i^{0} = \infty \quad \text{for all } i \neq 1 \]
\[ d_i^{h+1} = \min_{j}\big[\, d(i,j) + d_j^{h} \,\big] \quad \text{for all } i \neq 1 \]
Bellman-Ford with node 1 as the destination; stop when no \(d_i\) changes
\(d_i^{h}\) = estimated shortest distance from node \(i\) to node 1 after \(h\) iterations, in the link-length unit (for example delay) · \(h\) = iteration number (no unit) · \(d(i,j)\) = length of the arc from node \(i\) to node \(j\), \(\infty\) if there is no arc · \(j\) = a neighbour of \(i\) · label \((d_i, j)\) = distance and the next node \(j\) on the best path

The procedure in the lecture: label each node \(i\) with \((d_i, j)\); initialize with \((0, \cdot)\) at node 1 and \((\infty, \cdot)\) elsewhere; at each step \(h \gt 0\) find the \(j\) that minimizes \(d(i,j) + d_j^{h-1}\) and update the label to \((d_i^h, j)\); repeat until no \(d_i\) changes.

Filled in

Two facts the slides use without stating: \(d_i^h\) is the length of the shortest path from \(i\) to node 1 that uses at most \(h\) arcs, and since a shortest path never needs more than \(N-1\) arcs, the estimates stop changing after at most \(N-1\) iterations (positive link lengths assumed). The extra iteration in the lecture's table is the check that nothing changed.

Section 12Bellman-Ford strengths, weaknesses and oscillation

Advantage. The algorithm is very flexible about the initial estimates \(d_j^0\) (it still converges if it starts from other values), and it can be executed at each node \(i\) in parallel with every other node.

Disadvantage. It uses only one path per origin and destination pair, which can limit throughput. Its ability to adapt to changing traffic is limited by oscillations: when link delays depend on traffic, some shortest paths change, traffic shifts abruptly to the new path, which changes the delays again.

\[ D_{\text{A}\to\text{D via R}i} = d(\text{A}, \text{R}i) + d(\text{R}i, \text{D}), \qquad \text{A chooses } \min\big(D_{\text{via R1}},\ D_{\text{via R2}}\big) \]
the path delay each route advertises, and the single-path choice that causes oscillation
\(D\) = total delay of a path from A to D (delay unit, no specific unit in the lecture) · \(d(\cdot,\cdot)\) = delay of one link, which grows with the traffic on that link · \(e\) = a small positive extra delay on the R2 path (no unit given) · B = A's traffic rate, in bit/s
Example 19 (lecture): oscillation between two routes
Source A is attached to routers R1 and R2, both of which reach D. Links A to R1 and A to R2 have no delay of interest. With no traffic, delay \((\text{R1},\text{D}) = 1\) and \((\text{R2},\text{D}) = 1 + e\). When A sends all its traffic (B bit/s) through a router, that router's link to D has delay 10 (R1) or \(10 + e\) (R2).

Step 0. No traffic yet: compare \(1\) with \(1 + e\). The R1 path is shorter, so A sends all its traffic (B bit/s) to D via R1.

Step 1. The R1 link is now loaded: \(d(\text{R1},\text{D}) = 10\), \(d(\text{R2},\text{D}) = 1 + e\). The routers advertise these delays to A, which finds that the preferred path to D now starts with R2, so A moves all its traffic to R2.

Step 2. Now \(d(\text{R1},\text{D}) = 1\) and \(d(\text{R2},\text{D}) = 10 + e\), so R1 looks better again and A switches back.

\[ \begin{aligned} \text{step 0:}\ \ & 1 \lt 1 + e &&\Rightarrow\ \text{all via R1}\\ \text{step 1:}\ \ & 10 \gt 1 + e &&\Rightarrow\ \text{all via R2}\\ \text{step 2:}\ \ & 1 \lt 10 + e &&\Rightarrow\ \text{all via R1}\ \ (\text{and so on}) \end{aligned} \]

As a result, the situation alternates between the two paths. A better strategy would be for A to send half of its traffic to R1 and the other half to R2.

Traffic flips between R1 and R2 every update; splitting it half and half is better

Optimal routing removes both disadvantages: it directs traffic along paths that are shortest with respect to link delays that depend on the traffic flows the links carry, and it can split a flow across several paths.
